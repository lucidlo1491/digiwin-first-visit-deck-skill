# Acceptance Criteria — /digiwin-deck-visual (per visual TYPE)

Every visual must pass the **universal ship-gate** AND the criteria for its TYPE. Verified by render-and-READ in
中/EN/ไทย (sighted) — never "looks fine." If it fails, **re-route or remove; never ship filler.**

## §0 · ANTI-SCENT GATE — designed from THIS company, not reskinned from the last (Peter 2026-07-17)
**The scent = starting a slide from the previous deck's (or the scaffold's) ARGUMENT visual and swapping text, so the structure keeps arguing the OLD company's logic and inherits the OLD company's claims/needs.** (The S8 burn: the Unilever "ERP-brain → floor stations → eMES execution layer" diagram was reused for Thanakoon and text-swapped — it fabricated a *factory-automation need Thanakoon never expressed*, and its shape argued Unilever's floor-visibility logic, not Thanakoon's greenfield "three books, no ERP" reality.)

**REUSE is graded — this is the fix, not "never reuse":**
- **REUSE freely:** LAYOUT / craft blocks — stat-row, card grid, chrome, cover, `.pq` shell, presenter window. That's the *brand*, and where every past correction lives.
- **NEVER reuse:** an **ARGUMENT visual's STRUCTURE** (a diagram/chart whose *shape* encodes a specific mechanism) or its **FRAMING / CLAIMS**. Redesign the argument-shape FRESH from THIS slide's claim.

**Two tests EVERY argument / pain / fit / industry-focus slide must pass — a QA agent checks each as a binary:**
1. **SWAP TEST — would this slide's visual + framing work UNCHANGED for a DIFFERENT company (swap only the name)? If YES → FAIL.** The shape must be so specific to THIS company's mechanism it can't be lifted. (S8 PASS: "Bangkok-trade Excel + Saraburi-factory Excel + outsourced books, joined by a broken chain, CEO can't see the group P&L" is Thanakoon's exact three-islands — unliftable. S8 FAIL: "ERP brain → 5 floor stations" fits any factory on earth.)
2. **PROVENANCE / NO-INHERITED-CLAIM — every claim, need, and frame on the slide traces to a source fact** (【OSINT / 逐字稿 / Nova】), named in the ledger `source-fact` column. **A claim or need the customer never stated — inherited from the reference deck or invented — is an AUTO-FAIL, hedge or not.** (The automation-factory claim traced to NOTHING → cut. "Content uncertainty is asked, never guessed" applies to the SELLER's claims too.)

**How the QA agent checks it (the gateway):** for each visual slide, read the render + its ledger `source-fact` + the OSINT/Nova, and answer three binaries — (a) does every claim/need on the slide trace to a real source fact? (b) swap test: would it fit a generic company? (c) is the structure a scaffold-default or prior-deck argument-organism? **Any bad answer → FAIL, name the slide + the inherited element.**

**Mechanically enforced:** the `visual_audit.tsv` ledger now carries a **`source-fact`** cell per visual slide (a slide with none is templated by definition) + a **`swap-test=pass`** verdict; and `slide_gate.py`'s **`reskin-suspect`** check flags any scaffold-default argument-organism skeleton left intact (redesign, or justify with `<!-- FRESH: why this shape is THIS company's, not the scaffold's -->`).

## Universal ship-gate (every visual)
- **Real-job test** (graphics-law §0.5): does it make the slide more **conveying** (lands faster than text) · **convincing** (real proof/credibility) · **attractive** (on-brand, elevates)? Then the **removal test** — delete it; is the slide worse? If "no difference," it was filler.
- **Serves the slide's ONE message, comprehensible at a glance.** A technically-correct visual that confuses still FAILS (the S12 sankey→donut lesson).
- **SEMANTIC ENCODING matches the claim — every visual carries meaning in its *direction, size, position, and colour*; each must AGREE with the message.** Write the intended reading of each encoding, then verify the render says it: an **arrow** points the way the force/flow actually goes (the S3 burn: 售價↓ + 成本↑ must converge *inward* on 利潤 to read "squeeze" — outward read as release); a **bar/area** grows toward "more"; **coral = pain**, blue = solution (never inverted); higher/bigger = the thing that's actually higher/bigger. A visual whose encoding contradicts the words is WORSE than no visual — it teaches the opposite. **Self-check, per visual: "if I read ONLY the shapes/arrows/sizes, do I get the same conclusion as the headline?"**
- **Warehouse-only styling** — semantic tokens (Smart-Blue #00AFF0 / Royal-Blue #003CC8 / Navy #000864 / Coral #FF6E82 = pain), 8-pt grid, shopped icons. No invented hex.
- **Right TOOL for the type** (the router). **AUTO-FAIL:** a shape/box behind-or-beside text "to have a visual"; a dumped AI image; generic stock/clip-art; a visual that just restates the words; a chart that doesn't argue; **"shapes-combined."**

## A · ICON / PICTOGRAPH
- Shopped via `digiwin` MCP `find_icon(intent)` — **communicative** (the concept reads), never a generic line glyph.
- Brand-skinned (currentColor / smart-blue; pictograms recolored, not raw black). Legible at projection distance. One concept per icon. Used to label/anchor — not as the slide's only "informative" element when data exists.

## B · DATA CHART  (`scripts/gen_chart.py` — DigiWin-themed ECharts)
- **Right chart for the question:** single ratio → **gauge**; part-of-whole → **donut/pie**; flow/split → **sankey**; hierarchy/genealogy → **tree**; compare → **bar**; trend → **line**; multi-axis profile → **radar**. (Don't force a sankey on a 97/3 split — the S12 burn.)
- **Real chart grammar:** zero baseline; distinct axis/series; **no lines through bars**; no redundant 2nd chart; labels legible at projection.
- DigiWin theme applied; **baked text minimal/neutral** (numbers, OEE, %) — trilingual copy in the deck layer OR render one PNG per language.
- If the figures aren't the client's verified data → **hedge it** ("產業普遍現象 · 示意 / illustrative"). Never present an illustrative value as their number.
- **★ A chart whose STRUCTURE mirrors the client's OWN real trajectory is RECITATION even when tagged 示意 — VP-veto.** The hedge label does NOT launder it. (Burn 2026-06-30: Win Chance S13 had a 5-yr **21%→10% margin-decline line** — that *is* their real ~20→10% trajectory; an "illustrative" caption can't undo "we charted your falling margin and handed it back to you.") Two failures at once: it recites their financials AND encodes the wrong claim (a falling-margin *time-series* ≠ the slide's claim "you can't compute per-SKU true cost"). Fix = an **illustrative COMPOSITION** with generic indexed numbers that depicts the *mechanism*: book cost vs hidden true cost (60% / yield+variance+labor 40%) as a stacked bar — argues the headline, recites nothing. Rule: never bake a client's actual financial trend into a chart, hedged or not; use neutral composition/ratio structures.
- **★ A bare single-number gauge is AMBIGUOUS for a composition message.** "65%" on a dial doesn't say 65% of *what*, nor which side is the pain (Everydayhappy S12 working-capital). When the message is a split (free vs trapped, visible vs hidden), use a **labelled stacked/diverging bar** (26% cash / 42% inventory / 32% AR) so the trapped majority is self-evident — reserve the gauge for a genuinely single, unambiguous ratio (e.g. "60% of CS time on manual keying"). A small honest pain-slice (14–15% offcut/write-off donut) is FINE — coral=pain correctly; do NOT inflate it to dramatize.
- **★ The viz STRUCTURE must DEPICT the pain's mechanism — a lone illustrative dial is an AUTO-FAIL.** A gauge with a single round % tagged 示意/illustrative ("65% · ตัวอย่าง") that doesn't depict the mechanism argues NOTHING (removal-test fail) — worse than text. Pick the type whose SHAPE argues THIS pain: *cash trapped in inventory+AR* → grouped/diverging bars (revenue ↓ vs inventory+AR ↑, indexed 100/91/151) or a working-capital scene, **NOT a 65% dial**; *small loss, invisible* → part-whole donut (97/3); *traceability breaks* → genealogy tree; *flow loss* → sankey. Illustrative numbers must be **indexed/ranged so the STRUCTURE carries the argument** (100→151), never a bare value invented to fill a gauge.
- **★ NEVER reuse the prior deck's pain organism with a swapped number — that is TEMPLATING, the #1 regression.** Each pain slide's visual is DESIGNED FRESH from THIS company's pain mechanism. (Burn 2026-06-30: Everydayhappy / P.Inter / Win Chance S12–14 degraded into reskinned copies of King Pac's charts — "slapping on numbers" Peter rejected. King Pac S12–14 work because the donut/sankey/genealogy-tree each depict THAT pain; a dial copied across decks depicts none.)

## C · DIAGRAM / SCENE  (inline SVG)
- Argues ONE claim with a real metaphor + a **connector** that ties viz→point. Shows the **RELATIONSHIP**, not parallel lists (e.g. brain→nerves→stations as one structure).
- **CONNECTOR INTEGRITY — MEASURE, don't eyeball.** Every line/edge/arrow that should connect two elements must actually **touch** both ends — endpoint-to-target gap ≈ 0 (or a few px *into* the target). A reader-scale PNG **hides a small gap** (the S8 burn: SAP→station lines floated 8px above the boxes; the straight centre line showed it, the curves masked it — found only by measuring). **For any connector diagram, assert each endpoint's rendered screen coord ≈ its target's edge (Playwright `getBoundingClientRect`) before sign-off** — never trust the eyeball. Watch SVG `preserveAspectRatio`/`overflow:visible`: endpoints can land off where you think.
- **Craft bar:** gradients / depth / a hero element — **NOT flat primitives boxed beside text** (the S3 burn). 8-pt grid.
- **DEPTH RECIPE (lifts a flat diagram to designed without re-tooling) — verified 2026-06-30:** give node boxes a subtle vertical gradient fill (`#fff`→`#E9F0F8`) + a soft drop-shadow (`feDropShadow dx0 dy2.5 stdDeviation3.5 flood #000864 @0.16`); make the focal/pain node a **filled** coral-gradient (not a thin outline) so the eye lands on it; bump the key connector's stroke-weight. **Apply `filter=` ONLY to filled `<rect>`/`<circle>`/`<g>` (real area)** — never a line/stroke-only path (svg-robust). **feDropShadow on filled shapes renders IDENTICALLY in the PDF** (checked the actual export) — it's the zero-area case that blanks. **Use UNIQUE gradient/filter IDs per diagram** (e.g. `w14node`/`p12ds`): `url(#id)` resolves document-wide, so two diagrams in one deck file sharing an id collide. This is the right move when the diagram already ARGUES correctly — polish it; do NOT re-tool a sound diagram into a chart.
- **SVG ROBUSTNESS — renders identically in PDF + every browser, not just my Chromium screenshot.** NO `filter=` (blur/glow) on a `<line>` or stroke-only (`fill="none"`) `<path>`/`<polyline>`: a thin/straight connector has a near-zero-area bounding box, so the filter region is empty and the element paints **BLANK in PDF and non-Chromium** while Chromium leniently shows it — I "verify" a line the customer never sees (the S8 centre-line burn). Use a **solid stroke**; put glows only on shapes with real area (`<rect>`/`<circle>`/`<g>`). **Gate-enforced** (`slide_gate.py` `svg-robust`). Then verify on the **actual deliverable** (export the PDF, READ the page) — not only the live HTML render.
- Trilingual SVG `<text>` purity (paired t-zh/t-en/t-th); CJK `.nw` no-break segments. No clip-art.

## D · ILLUSTRATION / IMAGE  (`scripts/gen_image.py` nano-banana, or sourced)
- **Real-asset-first** — never fabricate a client's real factory/cert/logo/product. AI-generation is for **hero / atmosphere / background only**, never for data or exact-brand precision.
- Generated: brand-consistent prompt (navy→smart-blue, manufacturing context, **no baked text/logos**); labels added in the deck layer for language purity.
- Processed with `magick` (crop 16:9 / object-position / tint / frame) + **subtle & scoped** (no full-bleed image fighting the text; use a scrim + low opacity behind copy — the cover burn). Strip metadata.

## E · PHOTO  (sourced)
- The customer's / Digiwin's **REAL** asset (their site / Drive). Cropped CLEAN — no slivers, no text-bands, no merged montages, no competitor/wrong-geography labels. On-brand frame, legible, rights OK.

## Sign-off
Return: the asset (inline SVG block / PNG in `assets/`) + a render PNG (3 langs if it carries text) + one line "what it shows/argues." Show Peter. Canonical law: `references/graphics-law.md` · image recipes: `references/image-ops.md`.

## Data-chart craft bar (Peter 2026-07-19 — the AMK S11/S12 double-correction; JUDGMENT criteria the gate's `chart-self-labeled` check cannot fully see)
1. **SELF-LABELED, IN THE CHART LAYER, PER LANGUAGE.** Every label a viewer needs (categories, legend, center/summary text) is BAKED into the chart via the engine spec and rendered once per language (`c-zh/c-en/c-th`). An HTML caption/legend row beside a chart image is an AUTO-FAIL — two layers can never center against each other. `c-all` is legal only for purely numeric baked text (declare `<!-- LANG-NEUTRAL -->`).
2. **PICTORIAL WHEN THE QUANTITY HAS A PHYSICAL METAPHOR.** Money → coin stacks (pictorialBar), goods → box stacks, time → calendar strips. A plain bar/donut for a metaphor-rich quantity must justify itself; the engine does pictorialBar natively — use it. (AMK S11: plain bars → coin stacks was the difference between "a chart" and "money parked on a shelf.")
3. **THE CHART CARRIES ITS OWN CONCLUSION.** A waterfall gets its dashed bridge line and a summary annotation ("報價→實際:−40"); a comparison names its winner. If the viewer must read the slide body to know what the chart concluded, the chart is unfinished.
4. **REFERENCE-BAR QUESTION (ask during the sighted READ, per chart):** "Would this chart look at home beside the Tatung/SATS reference charts?" If plainly weaker — bare marks, floating labels, empty center — verdict is `re-tool`, not `keep`. A `keep` on a below-reference chart is the dishonest-keep failure mode the gate cannot catch; this question is the ceiling.
